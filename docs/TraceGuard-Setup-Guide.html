TraceGuard
Setup Guide
Get running in 4 steps

A quick, visual walkthrough — open TraceGuard, choose your application, point it at your source, and you're ready. Follow the numbered arrows on each screen.

For: Managers & the Release Team  •  Time: about 5 minutes  •  Classification: Internal use
Step 1 of 4

1Open TraceGuard

Launch the app — no install, no setup files to edit.

🛡️

Double-click the TraceGuard launcher. A small console window opens and stays open while you work.

It then opens automatically in your web browser. If it doesn't, type the address below.

Your browser
http://localhost:8080
That's the whole install. The only thing that needs to be on the machine is git, and only for the Release Impact tab. Everything else just works.
Step 2 of 4

2Choose your application

TraceGuard covers two applications. Pick the one you're releasing.

1Mighty — click Open to enter.
2TMRW — click Open to enter.
The three tabs — Release Scope, Release Test, Release Impact — work the same in both. You can switch application any time from the top bar.
Step 3 of 4

3Point it at your source & analyse

Tell TraceGuard where the code is and which release to look at, then press Analyse.

1Source — a Local folder or a Bitbucket branch.
2Path / repo to the module's code.
3Country for the release.
4Release version (or N/A for the latest).
5Analyse modules — you're set up.
⚙Config lives up here (Step 4).
Step 4 of 4 — one-time

4One-time settings (⚙ Config)

Open ⚙ Config from the top bar. Set these once — they're saved on your machine.

1Splunk base URL — lets Release Test build one-click log download links.
2Save the tokens & Splunk address.
3Interface Spec — attach this VAL report…
4…and the Capability Matrix — together they unlock the Capability Matrix export in Release Test.
Optional but recommended. You can skip Config to just trace and test. Add the Splunk URL when you want log links, and the two VAL reports when you want the "how to test" export.
You're ready

Pick a tab and go

Each tab answers one question — and exports a report you can share.

Release Scope

See what an API touches — routes, backends, versions.

Release Test

Prove the release worked, from your logs.

Release Impact

See what changed since the last release.

Need more detail? The full walkthrough of each tab is in the TraceGuard Product User Guide.
